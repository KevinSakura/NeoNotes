# 乐曲键盘扒谱：实施设计

2026-10-28。本轮明确授权覆盖此前仅设计的等待状态。接手时所指定的 v3 文件不存在，设计正文实际为 [v2 文件](v2-keyboard-transcription-plan.md)；该历史文件保留，本文件记录最新范围与实际选择。交付和证据见 [交付文档](transcription-delivery-20261028.md)。

## 产品边界

创作、练习、扒谱三个独立顶层入口，默认仍为创作；切换保留创作草稿，暂停音频并释放输入。扒谱数据与任务独立，不依附歌曲或练习。复制到练习／创作保留能力标识和来源结构，本轮返回未开放，不执行跨模块写入。

独奏：MP3/PCM WAV → 检查 → 选段解码 → Transkun → 校验 → 原始MIDI。混音：解码 → Demucs piano → 等待试听 → 用户明确继续 → Transkun；后台测试继续标记技术操作，不代表人工听感通过。不做模型基线平台或排名，不做伴奏、改编、训练、声音定制及歌声合成。

## 实际选型

- React/TypeScript/FastAPI/Mido/FFmpeg保持。使用已有 MusicXML 生成函数和 OSMD 语义映射组件，不调用练习导入、不套用键盘可达性。
- Transkun 2.0.1，官方wheel固定版本，V2 No Pedal Ext，MIT。官方wheel的源码与权重保留原状；Windows缺C++编译器，完整安装的ncls构建失败，但源码核对其仅为训练数据区间查询的局部导入，推理使用独立显式源码路径。详见准备脚本和清单。
- python-audio-separator已核对：它是多模型包装器，当前依赖包含samplerate源码构建及额外ONNX组件；本轮只需一套许可明确的钢琴输出，直接通过可替换适配入口调用Demucs4.0.1的htdemucs_6s。不是另搭基线。官方承认piano串音/伪影，本地受控样例也出现贝斯串入，混音保留试验标识。
- PyTorch/torchaudio2.8 CPU，4线程，重型任务最多1个。没有使用CUDA、改变歌声资源或安装额外Python环境。
- 资源通过 `scripts/setup_transcription.ps1 -PrepareModels` 或 `scripts/prepare_transcription.py` 显式准备；应用导入、启动、状态查询不下载。

## 数据合同与任务

`data/.transcriptions/<32位ID>/`：`source/`原音频；`project.json`当前修订指针；`jobs/<ID>/`参数、状态、日志及工作文件；`results/<ID>/`完整发布的片段、人声以外的钢琴音频、原始MIDI及秒级音符；`revisions/<ID>/`校对音符、设置、演奏MIDI和可用的整理MIDI/MusicXML。导出在对应不可变版本中，不另复制到可覆盖的公共下载目录。

事件：稳定id、pitch0–127、onset/offset片段秒、velocity1–127、hand auto/right/left。保留模型MIDI原字节及控制事件列表；校对MIDI暂只写音符，界面明确提示不编辑踏板。原始转录最多5000个片段内音符、8MiB；不因音域不适合电脑键盘而删音。

模型补帧边界采用clip-intersection-v1：在片段内起音但延伸至片段外的音符仅裁末端，完全在片段外的补帧音符不纳入校对；report记录原始时间、音高及数量，原始performance.mid不改。另产出clip.mid，保留片段内MIDI通道/音色/变速/控制信息，并在终点关闭持续音和踏板；格式为合并轨的Type0，原轨道结构继续保留在原始MIDI。最多16秒模型补帧窗口，恶性越界或非法起止仍拒绝。校对和SoundFont使用边界内音符，新结果明确展示处理说明，旧结果不重算。

`source_seconds = clip_start + clip_seconds`，解码/分离未另施加偏移校正，不能宣称测得零模型延迟。演奏MIDI技术速度120 BPM、480PPQ（约0.52ms舍入）；整理另用用户确认的BPM、拍号、第一强拍和网格。原始秒数始终不变。

状态：queued → decoding → separating → awaiting_review → transcribing → validating → succeeded，另有failed/cancelling/cancelled/interrupted。等待试听时释放计算资源；同工程需处理或取消等待项才能发起新任务。任务与修订操作检查当前基础版本、受锁保护，成功结果不覆盖。失败/中断后由用户重新点开始创建新ID，不自动重试或续算。

本地子进程使用现有Windows Job Object生命周期保护，退出/取消回收，进程每步超时30分钟。源码/权重逐项哈希检查，模型变更拒绝混用。文件下载检查版本清单与哈希，未发布结果不提供下载；分离试听只在完整长度检查后的awaiting_review阶段开放。暂不提供工程删除。

## 校对与记谱

表格编辑每个音符的音高、起止、力度和左右手；增加/删除，撤销/重做。保存新建修订，旧修订可查看、下载；保存旧修订内容时明确提示会新建当前版本。无隐式和声修复。

先按相同起止构成和弦，再以非重叠和音区连续性分配声部；声部音区排序建议左右手，逐音手动覆盖后重新分配每手声部。不是固定中央C分界。支持每手最多32个独立声部，不改变音符来凑声部；仅极密重叠超过安全排版上限时拒绝成谱。v2记谱带voice_stride=max(2,双手最大声部数)，MusicXML及OSMD语义映射共同使用，使右手3号和左手1号不会重号；旧格式缺字段继续按2处理，不自动迁移。记录/显示实际双手声部数，长音分段只增加谱面延音线、不增加实际起音。

恒速30–240 BPM；2/4、3/4、4/4、6/8；第一强拍可为片段内的弱起终点或负秒的前置强拍；调号用户确认。网格支持四分/八分/十六分/三十二分/八分三连音或不量化。显示最大偏移。零时长、无法分解时值或复杂重叠阻止成谱，不删音凑谱。包含谱号、拍号、调号、休止、小节、和弦及同一长音拆分的延音线；相邻重复同音不合并，无圆滑线推断。

恒速以外的自由速度整理、自动节拍估计、自动调性恢复、专业复杂记谱排版、波形拖选、PDF和跨模块复制未实施；多声部基础排版已支持。试听包含原始选段／分离钢琴／SoundFont演奏音符，共用片段定位；旧谱显示来源版本，草稿未保存不冒充已更新谱面。

## 验收边界

后端/浏览器模拟验证任务、保存、冲突和交互；真实本地推理验证音频输入到MIDI，不等于准确性。原创渲染钢琴及钢琴+贝斯、用户提供Canon前20秒各自记录来源/文件哈希/实际输出。错音、漏音、踏板尾音及分离串音由用户试听校对。不得把假响应、通过构建或输出MIDI当作音乐效果通过。
