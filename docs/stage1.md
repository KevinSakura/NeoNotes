## 可用功能与模拟边界

可用：新建/切换歌曲、键盘/鼠标试弹、四类合成音切换、原始演奏录制/回放与加入乐谱、歌词 TXT 上传及连续选段、文字要求保存、音符增删/移动/时长/力度、轨道音色/音量/独奏/静音、手动保存、跨刷新/重启的版本撤销/重做及历史恢复、基础 MIDI 实际导入和多轨导出。

第一阶段试听是合成音，部分 Program 使用相似波形，不是完整 GM 音色库。当时真实音质、延迟和后端渲染未验收；随后资源检查确认了用户的 GeneralUser GS。现已在获授权的第二阶段接入真实音色和音频导出，见第二阶段记录，不把这些后续工作计入首阶段验收。

AI、自然语言修改、MP3 与全曲按钮明确禁用。主题、歌词与情感仅保存，尚没有音乐对应算法。新歌的 1 分钟空白时间轴不构成生成了 60 秒编曲。原型与正式工程分开，不读取原型 localStorage。

## 数据协议

歌曲用稳定 ID 定位，与显示名称分离，保存至 `data/<歌曲ID>/`。同名歌曲可并存。

- `project.json`：歌曲显示名、创建/更新时间、当前版本、全部已提交版本索引，以及撤销/重做栈。
- `revisions/<版本ID>.json`：不可变版本快照，含序号、操作标签、父版本、保存时间、统一 `SongState`。
- `inputs/<版本ID>/`：输入 JSON、歌词文本和原始演奏 JSON。
- `inputs/originals/`：用随机文件 ID 保存上传原始字节；来源信息含文件名和 SHA-256，不用上传文件名拼接磁盘路径。
- `exports/<版本ID>.mid`：导出的实际音乐交换文件；没有导出时不存在。

`SongState` 使用 `schema_version=1`，由 `inputs` 和 `score` 构成。

`inputs` 保留主题、情感、歌词全文、连续选段行号、旋律模式、原始演奏和来源文件。演奏保留秒级起始/持续时间、音高、力度、录制声部 ID、乐器类别和 Program。电脑键盘没有力度传感，当前固定 90，可在编辑后调整。

`score` 使用 480 PPQ、绝对 tick、完整速度/拍号变化、轨道和支持的 MIDI 元事件。音符含独立 ID、pitch、velocity、start_tick、duration_tick；轨道保存 Program、Bank、Channel、鼓标志、音量、静音和独奏。

原始录制秒数不被编辑覆盖；加入乐谱按当前速度图换算 tick，不做节拍量化。MIDI 文件用于交换音符和乐器信息，歌词选段、历史和试听静音/独奏状态由工程保存，不能只靠 MIDI 恢复全部歌曲材料。

保存先写不可变材料与版本，再原子替换工程指针。失败不推进当前版本；残留未索引文件不自动删除。保存接口要求基础版本，过期写入返回 409。后端只支持单进程写入，多实例、磁盘损坏和电源故障的全面恢复尚未承诺。

## 操作与保存规则

默认显式手动保存，显示未保存提醒。上传和 MIDI 导出会先保存草稿。新建、切换或恢复历史之前，如果有修改，用户选择保存、下载草稿或明确放弃。

当前会话的音符操作保留本地撤销栈（最多 100 步）；保存后由磁盘版本栈负责撤销/重做，刷新和重启继续有效。撤销已保存版本会同时恢复该版本输入与乐谱。恢复历史产生新版本，旧文件保留。

失焦或页面隐藏停止录制、释放所有音符并停止试听。录制状态显示就绪后开始电脑按键。音频启动失败时提示用户，不能假称有声音。

## MIDI 范围

基础 PPQ Type 0/1，最多 2 MB、16 个独立声部、5000 个音符和 10 分钟。自产歌曲初始四声部，外部歌曲保留其轨道结构，不强行四轨化。

保留音符、速度/拍号变化、开头 Program/Bank/音量、轨道名、调号、支持的文字/歌词/标记及乐器名称。Type 1 导出有独立速度轨、轨道名与实际乐器设置；GM 鼓使用代码通道 9，即用户所见第 10 通道。导出完整乐谱，试听独奏/静音不删除音符。

明确拒绝 Type 2/SMPTE、多个轨道共用通道、途中乐器/控制变化、其他控制器（包括踏板）、弯音、SysEx、未知元事件和未配对音符。拒绝发生在乐谱提交之前，不覆盖作品。支持范围内也会重组元轨道、转换 PPQ/音量精度，不声称任意 MIDI 都可无损编辑。

## 文件职责

| 文件 | 输入与输出 / 修改位置 |
| --- | --- |
| `backend/app/models.py` | 校验输入、音乐数据、音符范围、时间、声部和歌词连续选段。 |
| `backend/app/storage.py` | 歌曲 ID 与版本请求 → 独立目录、不可变快照、原子提交和历史指针。 |
| `backend/app/midi.py` | MIDI 字节 ↔ 统一乐谱；含 PPQ、速度图、实际乐器和鼓语义处理。 |
| `backend/app/main.py` | 本地 API、上传/下载、错误提示、主机/来源/会话检查及前端构建文件。 |
| `frontend/app/src/App.tsx` | 中文工作台、输入/录制/编辑、保存和冲突处理。 |
| `frontend/app/src/PianoRoll.tsx` | 完整音符时间轴、选择、网格新增及音符自动定位。 |
| `frontend/app/src/audio.ts` | 用户启用音频、合成音、基于音频时钟的事件提前调度、停止与释放。 |
| `frontend/app/src/music.mjs` | 拍与秒换算、回放事件、连续选段；有独立逻辑检查。 |
| `scripts/start_local.ps1` | 构建与正式本地启动；不自动安装、不打开个人浏览器。 |
| `scripts/run_e2e_server.py` | 隔离测试服务器，仅写 `.cache/e2e-runs/<测试ID>/data`。 |

主要接口：`/api/projects` 创建/列出；`/api/projects/{id}` 读取/保存；`history`、`undo`、`redo`、`restore` 管理版本；`lyrics`、`midi` 上传；`midi-export` 生成文件。写操作携带当前进程会话与基础版本。没有 AI 或音频生成接口。

## 剩余边界

当前为单用户、单进程、本地显式保存工作台；草稿 JSON 不提供导入，复杂 MIDI 不支持，音色仍为合成示意。长期文件增长、磁盘故障恢复、多实例并发和真实音质没有完成全面评测。

下一阶段首先处理音色资源许可与真实渲染。歌词可唱性、旋律保留规则、60 秒音乐结束及尾音口径、AI 质量与成本，需要在模型阶段另行验证，不由本阶段格式检查背书。
