# 歌词输入修复与字词上限调整

日期：2026-10-06。本轮修复现有第六阶段功能，未启动新阶段。按用户要求，短曲字词上限提高到256，整曲提高到1024；新增真实模型请求0次，未读取、修改或展示真实`.env`。

## 原因与歌曲状态

实际歌曲`3bb1828be24d4bb7a8088271d80277a8`的当前选段为15行、173字词，超过旧短曲120字词上限，后端在创建任务之前返回422。另一个已保存版本虽取消了歌词选段，但仍保存全文；原预检将这种状态误判为必须选段，阻止仅用音乐感觉或主题创作。上传TXT和直接粘贴都会经过相同检查。

该歌曲5个保存版本均能正常解析，没有生成任务记录，歌曲文件没有损坏。本轮不删除歌曲、不改写版本、不迁移正式数据，只修正输入校验与页面操作。

## 当前规则与操作

| 范围 | 字词上限 | 行数上限 | 歌词来源 |
| --- | ---: | ---: | --- |
| 60秒短曲 | 256 | 16 | 用户明确勾选的连续非空行 |
| 整曲及整曲整体修改 | 1024 | 64 | 全文全部非空行，按原顺序使用 |

中文字符逐字计数，英文按词计数，数字也形成字词单位，标点和空白不计入。页面显示已选行数、字词数和上限；超限提示实际计数，并在生成前阻止提交。后端仍独立校验，不依赖页面判断。

“取消歌词选段”只清空本次选段，不删除全文或上传原文件。有主题、音乐感觉或演奏时，可以生成无歌词短曲，存储的未选全文不会作为本次短曲歌词发送给模型。只有歌词且没有其他输入时，仍须明确选择歌词行，不能由程序猜测选段。整曲自动使用全文的规则不变。

修改涉及输入计数、音乐规划与保存结构的对应数量上限、模型提示和前端预检。没有放宽歌词覆盖、单旋律、音域、换气、60秒时长或人工审核要求；没有裁剪歌词、补发请求或覆盖旧候选。

## 使用更新后的版本

1. 在原服务终端按Ctrl+C停止旧服务，双击根目录[启动工作台.cmd](../启动工作台.cmd)。也可在项目根目录运行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_local.ps1
   ```

2. 刷新Chrome/Edge中的 **http://127.0.0.1:8000**，打开原来的歌曲。启动会重新构建前端，既有`.env`与SoundFont无需更改。
3. 原173字词选段现在符合数量上限。想按歌词创作时保留勾选；只想用感觉创作时点击“取消歌词选段”，填写音乐感觉即可，无需删除歌词全文。
4. 真实模式仍需用户确认本次发送资料及消耗额度后明确发起。通过输入检查仅表示可以提交，不保证模型结果通过后续音乐检查。

正式数据继续位于`data/<歌曲ID>/`，输入、原文件、不可变版本、候选和音频沿用现有目录。所有测试写入`.cache/`中的隔离目录；原歌曲的副本也仅存于该目录，没有向正式歌曲写入测试候选或审核。

## 模拟范围与剩余风险

本轮确认的是输入、生成流程、持久化保护与软件回归。边界候选和原歌曲副本使用模拟模型，假HTTP仅检查适配器分发，不是DeepSeek真实音乐效果验收；本轮没有追加完整音频渲染验收，既有音频流程浏览器回归通过。

256字词放进60秒仍可能过密；1024字词整曲也可能无法满足现有10分钟、5000音符或单次输出预算。模型未满足完整覆盖、换气等要求时仍拒绝候选，不通过删词或放宽标准冒充成功。整曲32768输出token规则不变，短曲仍尊重现有配置；不自动重试、拆请求或切换服务商。新上限和提示尚未真实调用验证，可唱性、曲风、声部配合及最终音质仍须人工试听/试唱。
