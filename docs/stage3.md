## 启动与配置

双击项目根目录 `启动工作台.cmd`，在 Chrome / Edge 打开 **http://127.0.0.1:8000**；也可从项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_local.ps1
```

所有Python由 `conda run -n piano` 运行。正式前端仍为 `frontend/app`，后端为 `backend`，HTML原型完整保留。本轮沿用已有Python及前端依赖，没有安装额外模型SDK。启动检查及打开页面不会发起模型请求。

只有运行中的后端按需读取根目录 `.env`，开发助手未打开或展示真实文件和密钥。仅加载 `MODEL_*`；APP、数据和音频工具路径仍由代码/脚本固定，`AUDIO_*` 与 Qwen 适配预留未实现。设置在进程内缓存，修改后须重启。

| 配置 | 当前约定 |
| --- | --- |
| `MODEL_MOCK` | 默认true：明确标注的确定性模拟、不联网；false：真实DeepSeek |
| `MODEL_PROVIDER` / `MODEL_NAME` | deepseek / 默认deepseek-flash；可配置deepseek-v4-pro，但本轮未验证pro |
| `MODEL_BASE_URL` | 仅允许官方https://api.deepseek.com 或其/v1；不跟随重定向 |
| `MODEL_API_KEY` | 只在真实.env本地填写；状态、错误和歌曲记录不包含密钥 |
| `MODEL_OUTPUT_MODE` | json_object；同时明确提示JSON，后端再检查音乐合同 |
| `MODEL_TIMEOUT_SECONDS` | 默认180，允许10..300；HTTPX连接上限10秒，超过响应时间检查失败 |
| `MODEL_MAX_RETRIES` | 仅允许0，没有自动重试 |
| `MODEL_MAX_TOKENS` | 默认12000，允许512..24000；本轮付费验收脚本额外硬限制12000 |

空密钥、无效配置或其他provider会阻止真实请求，编辑和已有音乐文件仍可用。配置错误只报告允许的字段名，不显示输入值；本轮修正了.env中数字字符串`MODEL_MAX_RETRIES=0`的加载兼容，并用假配置验证。

## 实际操作路径

1. 新建/打开歌曲，输入主题与音乐感觉，可选择歌词或录制片段，也可仅文字创作。歌词决定表达内容，音乐感觉独立规定呈现，允许悲伤歌词配积极曲风。
2. 在创作输入页确认本次发送所选资料及付费，点击生成。输入先保存；一个任务最多一次HTTP请求，进度和失败原因可见。
3. 成功候选单独保存，不覆盖当前乐谱。可用本地SoundFont试听、查看字词对应及下载候选MIDI；需要明确点击“采用到编辑器”才创建歌曲新版本。
4. 修改音符、混音并保存，或在编辑页输入整曲修改要求，生成新的候选并明确采用。采用后可撤销，旧版本保留。
5. 在保存与导出页试听实际渲染声音、导出MIDI/WAV/MP3；对当前保存版本人工确认旋律、伴奏、曲风，有歌词时亲自照词试唱。

人工审核保存与当前版本绑定。修改并保存新版本后，旧审核不能标记新版本通过；撤销回旧版本可查看对应旧审核。删除对应音符、改变歌词或使时间范围无效会阻止审核通过。未保存草稿不能提交审核。模拟曲的审核明确标注为模拟，不是模型效果验证。**通过也不会自动生成全曲；全曲按钮始终禁用。**

生成中的输入版本不可被后来保存覆盖；旧候选仍可试听/下载，但不能覆盖新保存的作品。候选采用重复提交不会再建相同版本。多个页面使用基础版本冲突保护。

## 音乐合同与可唱性边界

模型通过单次请求返回共同段落、和声、四声部事件及歌词映射，不执行模型生成代码、工具调用或Base64 MIDI。Pydantic检查后，由Mido生成真实Type1 MIDI：一个时间轨、键盘/鼓/吉他/贝斯轨，实际Program/Bank/音量写入，鼓为零基9号通道。真实SoundFont预设也须可用。

- AI范围：60秒乐谱时间轴，容差0.001秒；4/4，BPM60..160且为4的倍数，最多1200音符。手动/MIDI工程仍保留原有10分钟、5000音符、16声部范围。
- 至少2个共同段落；段落和和声各自连续覆盖整曲。各声部至少在2个段落有音符，整体发声间隙不超过3秒，最后音符距结束不超过0.25秒。音域、同音重叠、越界及静音内容均检查。覆盖检查不证明和声安排或音乐发展好听。
- 选段最多16行、120个中文字符或英文词，保留原行号和标点；完整歌词未选时先提示选段，未选部分不发给模型。中文字/英文词按顺序映射到主旋律音符ID，允许一字多音，不漏词、不重复引用。
- 有歌词时主旋律为单旋律，MIDI音高48..84，每音0.12..5秒，行间至少0.15秒换气。这些是初步检查，不是适用于所有歌手的安全音域，也不证明中文声调、重音、英文多音节、音节密度及实际可唱性合格。不合成人声。
- 演奏参考最多30秒、160音符。保留模式逐事件检查音高、力度、声部、Program/Bank，原秒级开始及持续时间换算后最多1 tick差异，不移调、量化或静默改写。未满足则拒绝，不靠模型声明“保留”算通过。本轮真实测试出现失败，稳定性待改进。
- 自由改编在提示中要求沿原上行/下行、重复和乐句延展；目前没有足以确认音乐语义利用的客观算法，需人工对照试听。不能用四轨和合法JSON代替旋律利用验收。
- 自然语言修改只接受整曲处理，暂限60秒、标准四声部和1200音符；发送当前乐谱和原输入，保留声部ID、通道、独奏/静音，重新生成音乐及对应。有明确局部/单声部要求时提示尚未支持；并非任意自然语言边界都能准确识别。

60秒验收针对乐谱，FluidSynth/FFmpeg沿第二阶段规则另加3秒尾音，WAV约63秒，MP3可能有少量编码延迟。额外尾音不算创作时长，格式/非静音通过不算主观质量验收。

## 数据位置与任务保护

正式作品仍在 `D:\study\AI_prompt_study\piano_keyboard_create\data\<歌曲ID>\`，没有SQLite，也不保存到原型localStorage。旧版本不迁移、不改写；SongState仍兼容schema_version=1，新版本增加可选composition字段，导入外部MIDI会清除原AI对应。

新增文件：

```text
jobs/composition/<任务ID>/
  input.json          # 保存版本的所选输入，整曲修改还包含当前乐谱
  job.json            # 状态、来源版本、模拟标记、错误、真实请求数、返回模型/ID/usage
  plan.json           # 结构检查通过的音乐规划
  candidate.json      # 可编辑歌曲候选及歌词对应
  candidate.mid       # 后端生成的真实多轨MIDI
reviews/<版本ID>.json  # 此版本最近一次人工审核
reviews/history/<审核ID>.json  # 不可变审核历史
```

后3个候选文件只在生成和校验成功后提供；失败仅保存任务/输入/可确认的用量，不保存原始HTTP响应。配置及密钥不进入这些文件。候选采用、编辑保存和撤销沿原有不可变版本机制；音频继续保存到 `exports/audio/<渲染ID>/`。

编曲队列一个工作线程，最多2个运行或排队任务，同首歌不重复排队；不自动渲染/采用/审核。超时、余额不足、限流、截断、空JSON、坏结构或不合规候选均失败且保留当前作品，不追加修复请求，不自动换Qwen。服务中断后不重发，无法确认是否计费会明确提示；用户需保留记录核对账单。HTTPX超时作用于网络操作，并结合读取时的经过时间检查，不保证网络异常时精确到毫秒终止。
