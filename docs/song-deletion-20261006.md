# 歌曲删除与回收站交付（2026-10-06）

本次按用户要求为已有创作加入整首歌曲删除，正式前端和本地后端均已接入。历史版本仍是不可变记录；删除移动整个歌曲目录，不逐个改写或清理历史。

## 使用与实际数据

停止旧服务，再双击根目录 `启动工作台.cmd`，访问 `http://127.0.0.1:8000`。

左侧每首歌曲旁增加“删除”。确认窗口显示名称和歌曲ID，并说明已保存歌词、原上传文件、演奏、所有版本、审核记录、AI候选及MIDI/WAV/MP3一起移入回收站。

- 正常歌曲：`data/<歌曲ID>/`。
- 删除后：`data/.trash/<歌曲ID>/`。
- 左侧“回收站”点击“恢复歌曲”，随后从歌曲列表打开。
- 恢复保留原ID、全部文件内容、版本编号、当前版本及撤销/重做指针，不创建新版本，不替换当前前端草稿。
- 删除当前歌曲会停止器乐及已渲染音频试听，清空编辑器与该歌曲的前端撤销记录，返回空白工作台。
- 未保存内容只存在当前页面，删除当前歌曲时会放弃；确认窗口提供下载草稿或取消后保存的选择。删除其他歌曲不放弃当前草稿。
- 刷新或重启后回收站仍存在。已下载到浏览器下载目录的文件不移动、不删除。

回收站仍占用磁盘空间，本次没有永久清空、自动过期清理、逐条AI候选删除或单个历史版本删除。备份整个 `data/` 应包含回收站目录 `.trash/`。

## 后端行为与保护

`DELETE /api/projects/<歌曲ID>` 必须携带当前 `base_revision` 和本地会话令牌。检查通过后，将整个目录在同一磁盘上重命名到回收站，无递归删除、无文件内容改写。

`GET /api/trash` 列出可恢复工程；`POST /api/trash/<歌曲ID>/restore` 使用会话令牌恢复完整工程。回收站不出现在正常歌曲列表里，已删除歌曲的普通读写接口返回不存在，旧页面不能写回并重建已删除目录。

删除检查与目录移动持有编曲管理器、渲染管理器和存储锁，防止检查后又启动任务：

- 本歌曲有排队/运行中的编曲或渲染任务时返回冲突，等待结束后才能删除；其他歌曲不受影响。
- 以当前进程的实际任务记录判断活动状态，不把旧进程中断的“queued”记录永久当作正在运行，也不为删除而重写旧任务状态。
- 另一页面保存了更新版本时拒绝旧确认；取消并重新打开最新版本后再确认。
- 只接受32位小写十六进制歌曲ID，拒绝目录穿越以及链接/Windows junction路径；仅操作当前存储根内的正常目录。
- 目标目录已存在时拒绝覆盖，目录移动失败时原位置及文件保留。

仍按现有单进程后端使用，不支持多个服务进程同时操作同一 `data/`。正在下载的文件或外部程序锁住目录可能导致移动失败，界面会提示文件读写失败；歌曲不会按失败操作被清空。
