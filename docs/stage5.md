## 5A实际使用

### 修复歌词对应

先采用一个带歌词对应的60秒候选，在“02 演奏与编辑”找到“手动修复歌词对应”。

1. 点击要修复的字词。界面显示原音高与时间；原音符被删除时明确提示对应缺失。
2. 在音符列表勾选现有键盘主旋律音符，可以一字多音，最多12个；按时间显示，已用于其他字词的音符有提示。需要替代音符时先在上方时间轴添加并调整。
3. 点击“确认绑定到这个字词”。服务端检查当前版本、候选来源、创作输入、歌词覆盖、音符归属、重复/顺序、单旋律、C3–C6音域、0.12–5秒时长、行间换气和原演奏保留约束。错误绑定拒绝，不写文件。
4. 合法绑定只更新草稿，点击“保存歌曲”后写入新版本，再到保存页试唱与重新审核。保存前音乐编辑和歌词对应一起撤销/重做；保存后仍可通过历史恢复，旧版本不改写，新版本不继承审核。

多个字词缺失可逐个修复：允许其他未修复引用暂时存在，结构报告仍失败，不能提前审核通过。修复不猜测字词或替代音符，不改歌词、主题、曲风和原演奏；改变创作输入仍需重新生成。声部或原演奏本身有冲突时先修复乐谱，不能借绑定绕过检查。保存时按新对应更新MIDI歌词标记。

接口 `POST /api/projects/<ID>/lyrics-repair` 返回校验后的草稿和结构报告、`saved=false`；只有显式保存接口落盘。没有新增自动保存或AI局部修改。

### 慢速与循环练唱

在候选歌词详情或“03 保存与导出”的歌词试唱区选择1倍（默认）或0.75倍速度。勾选“循环这一句”后点击“听这一句”，会持续重复这一行；“只听歌词主旋律”仍为完整歌词单次试听。

慢速保持音高、力度、音色及音量，仅延长播放事件时间；歌词跟随换算回原曲秒位置，兼容原有速度变化和一字多音。准备和尾音也同步延长：原曲句前最多0.3秒、句后0.6秒。独听忽略其他声部与静音/独奏，不改动保存的混音。

停止、换句、修改速度/循环设置、切页、切歌、编辑、保存都会取消旧播放。使用同一个本地音色引擎，不叠加另一播放器；显式循环边界保留准备和尾音，并按已安装引擎的实际无限循环语义实现。歌曲JSON、BPM、MIDI及渲染文件不会因练唱改变。仍没有人声合成/识别，试听不自动勾选试唱或审核。

## 5B实际改进

保留原演奏时，预检枚举本阶段允许的BPM，用与正式编译相同的秒转tick函数检查固定前缀。若所有速度都会产生同音高重叠、歌词主旋律重叠，或四声部锁定窗口内出现无法填补的超过3秒整体空白，直接提示缩短/重录或自由改编，不创建任务、不请求模型。仍有未锁定声部可填补的空白不误判为必然失败。可行速度列表和原演奏中适合歌词分配的索引提示会进入模型输入，最终候选继续完整校验，不放宽规则。

合法的很短/很长参考音符可以保留为器乐前奏，不能硬分配给字词。确定性模拟器现在按可用参考音符与换气位置分配歌词，再接新音符；这仅改进流程验收样例，不代表真实模型已达标。

隔离评估脚本新增：

- `extend_lyrics`：和 `preserve_lyrics` 使用相同歌词、主题、曲风、录制，只改变旋律模式，供人工对照。
- `modify`：依赖之前已完成结构及音频链路的 `preserve_lyrics` 候选，不用自由改编结果替代。前者失败则跳过修改，不重发或换输入；真实模式还须明确采用这个结构候选。
- 输入/输出版本、预检、操作、模式、过滤数量、结构报告、音频文件和人工表分别记录。
- `reserved_attempts`保守预留验收次数，`actual_requests`/`live_attempts`记录HTTP实际分发尝试；预检或适配器初始化失败为0，连接超时的已分发尝试计1。这个数不能证明远端收到了请求或确定费用；没有有效用量时仍未知，没有自动重试。
- 为完成的候选生成 `human-review-<用例>.md`，逐项记录旋律、声部、曲风、原旋律利用、修改要求和逐行试唱，初始全部“未评估”。填表不会自动变成软件审核或模型质量通过。

离线综合验收命令（不加载真实配置、不联网）：

```powershell
conda run -n piano python scripts/evaluate_model.py --mock --cases preserve_lyrics extend_lyrics modify
```
