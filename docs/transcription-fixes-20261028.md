# 扒谱片段边界与多声部修复

日期：2026-10-28。修复用户报告的“转录音符时间超出片段”和“每手超过2个独立声部”，不改变模型、资源、真实.env、原始工程或旧失败结论。

## 实际问题

- 原工程的39–69秒独奏任务已完成模型推理，213个音符中只有MIDI81的末端超出选段：起音在片段29.730208秒，结束30.383333秒。旧校验一旦超过30.1秒就拒绝整首，因此没有发布完整结果。
- 同工程6份63音符修订使用120BPM/4/4/十六分网格，需要右手3声部和左手3声部。原实现每手硬限2；XML生成和OSMD映射也固定以2为左右手编号间隔，直接解除数量检查还会造成重号。

## 当前行为

### 选段边界

`clip-intersection-v1`按模型事件与所选时间范围求交，不重作曲：

- 起音在片段内、结束在片段外：只将用于校对/试听的结束时间截至终点，不移动起音或修改音高、力度。
- 起音完全在选段外：只作为模型补帧保留在原始输出，不当成所选片段音符；界面显示数量，结果JSON保留具体原始位置。
- 控制事件同样保留原始诊断，片段外控制不进入选段MIDI；在选段终点关闭仍持续的音符与踏板。
- 模型原始`performance.mid`字节不改；新增`clip.mid`下载，与原始文件分开，实际保留片段内音色、通道、速度变化及控制事件。选段文件合并为MIDI Type0；原来的轨道结构仍在原始文件中。
- 坏MIDI、未匹配松键、缺少音符结束、零时长、超出整个片段加16秒模型补帧窗口等仍拒绝，不通过任意吞错来发布结果。

新任务记录pipeline v2与边界策略，结果保存`boundary_report`及导出哈希。旧成功或旧失败不自动重新读取、改写或重分类。

### 多声部记谱

保留原来的和弦识别、非重叠/音区连续性和左右手手动覆盖；扩展至每手最多32个独立声部。数量上限用于极端密集重叠的排版保护，普通3、4等声部不再直接失败。

新记谱为`neonote-transcription-notation-v2`，带`voice_stride=max(2,双手最大声部数)`。MusicXML和前端语义映射使用同一间隔，因此双手各3声部时为右手1–3、左手4–6。缺少字段的旧记谱继续按2解释，练习和旧歌曲不迁移。

实际音符ID、音高、起止、力度、左右手覆盖及重复起音均保留；长音跨小节的谱面段仍用延音线连接。界面显示实际双手声部数。校验中还发现延音线遮挡音头点击，以及窄屏谱面撑宽页面，已分别修正非交互延音线的鼠标事件和工作区网格的最小宽度。

此修复不保证自动分手的音乐合理性，也不把声部多等同于模型转录准确。短音量化为零、时值无法表示等仍保留原来的明确提示，不自动删音或拉长。

## 如何使用修复

1. 停止旧后端，在项目根目录双击“启动工作台.cmd”，正常构建前端，浏览器Ctrl+F5刷新。无需安装依赖或重下模型。
2. 原39–69秒失败任务保留；在同工程填写原选段，重新点“开始转录”。新任务按边界策略处理并保留模型原始文件。也可下载新增的“选段MIDI”。
3. 已有63音符结果无需再次推理，打开原结果或修订，直接点“确认参数，保存并生成五线谱”，创建新的修订。旧失败修订不被覆盖。
4. 多声部谱面仍可点击高亮，窄屏可在谱面内部滚动。复杂左右手及节奏请继续试听校对。

数据位置保持`data/.transcriptions/<ID>/`。旧下载仍绑定旧结果，不让新算法在读取旧文件时悄悄改变内容。
