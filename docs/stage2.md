# 第二阶段：本地真实音色与音频导出

交付日期：2026-10-05。用户明确授权本阶段，第一阶段歌曲文件、编辑、历史与 MIDI 功能继续保留。正式前端仍在 `frontend/app`，后端在 `backend`，原型未覆盖。

## 启动与体验

双击根目录 `启动工作台.cmd`，保留终端，访问 `http://127.0.0.1:8000`。也可在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_local.ps1
```

全部 Python 使用 Conda `piano`。本阶段没有新增 Python 依赖，不创建 `.venv`。前端新增并锁定 `spessasynth_lib=4.3.14` 和 `spessasynth_core=4.3.22`，移除 Tone.js；新机器按 README 安装依赖与放置本地工具。

1. 创建歌曲，点击“开始录制”；首次加载本地约 31 MiB 音色，等待音色就绪与“停止录制”按钮出现再按键。
2. 切换键盘、鼓、吉他、贝斯试弹，停止并回放录制。音频电平表反映实际输出。
3. 把片段加入编曲，或导入支持范围内的 MIDI。手动编辑、试听、保存与历史操作沿用第一阶段。
4. 保存页选择按当前独奏/静音混音，或完整声部，点击“生成 WAV 与 MP3”。生成操作先保存当前草稿。
5. 等待完成，试听实际 WAV，分别下载 WAV、MP3。历史列表可切换版本试听与下载，旧结果明确标记，最多展示最近 30 次；所有已保存文件仍保留。

歌曲数据根目录为 `data/<歌曲ID>/`。正式试用产生自己的歌曲，自动测试没有写入正式示例。AI、歌词谱曲、自然语言修改、人声与全曲生成仍未接入；本阶段不加载真实 `.env`，不调用模型或付费服务。

## 音色与演奏

使用用户准备的 `tools/soundfonts/GeneralUser-GS-main/GeneralUser-GS.sf2`。文件内置名称实际为 **GeneralUser GS 2.0.3 BETA**，目录解析得到 287 项预设；随包文档写作 2.0.3，两者如实区分。大小 32,319,396 字节，SHA-256：

```text
9575028c7a1f589f5770fccc8cff2734566af40cd26ed836944e9a5152688cfe
```

浏览器通过受限制的本地固定资源接口读取音色，并核对 SHA-256；音频线程读取真实采样和音色包参数。工作线程文件由 Vite 从同版本依赖打包到本地，不使用 CDN。不需要将 32 MB 音色重复复制进前端，也不依赖声音请求经过后端。

试弹与回放使用同一个音色引擎；片段/乐谱回放先确认序列加载，再在音频线程调度，暂停或失焦时释放音符。回放秒数使用 0.1 ms 中间表示；原始秒级录制保留，正式乐谱与交换 MIDI 仍是 480 PPQ，不做节拍纠错。

新录制补充保存实际 Channel、Bank MSB/LSB，避免非默认预设回放丢失乐器信息。第一阶段没有这些字段的旧录制仍能读取，按原有乐器类别与默认 Bank 回放；打开时不迁移或改写旧快照。

当前采用 GS Bank 规则：旋律 Bank 为 CC0，CC32 必须为 0；鼓 MIDI 使用第 10 通道，SoundFont 使用 Bank 128，鼓 Bank MSB/LSB 必须为 0。需要的 Bank/Program 没有预设时明确拒绝，不让引擎默默换音色。MIDI 导入/导出仍保留原 Bank 信息，即使当前音色不能播放。

浏览器采用 SpessaSynth，导出采用 FluidSynth；均使用相同音色文件、音量和音符资料，关闭额外混响与合唱。两种实现的滤波、包络、采样插值等仍可能有差异，不承诺逐样本相同。导出前以保存页实际 WAV 为准。浏览器工作线程的集成依据 [SpessaSynth 官方说明](https://spessasus.github.io/spessasynth_lib/extra/working-with-browsers/)，GS Bank 处理依据 [FluidSynth 官方设置](https://www.fluidsynth.org/api/settings_synth.html)。

随包许可证保留在原位置；允许使用的声明及样本来源不完全可追溯的说明见 [LICENSE.txt](../tools/soundfonts/GeneralUser-GS-main/documentation/LICENSE.txt)。SpessaSynth 依赖为 Apache-2.0。发布或再分发时依据实际使用方式复核，不把格式/发声检查当作来源完整证明。

## 渲染、文件与版本

每个任务读取已提交版本快照，保留版本号、版本 ID、声部模式、音色名称/校验值、渲染方案版本、工具版本及参数。渲染过程中继续编辑不会改变正在生成的作品。

- `mix`：尊重保存版本的独奏、静音及音量。
- `full`：忽略独奏/静音，保留完整音符与音量；音量为零的轨道仍无声。
- 独立 MIDI 导出一直保留完整声部；不要将“当前混音”的渲染用 MIDI 当作完整工程。

输出存放在：

```text
data/<歌曲ID>/exports/audio/<渲染ID>/
├── render.json  # 状态、版本、模式、参数、来源、时长、电平与文件校验值
├── render.log   # 本地工具输出与错误详情，不由下载接口提供
├── mix.mid      # 该次渲染实际使用的音符/乐器
├── mix.wav      # 44.1 kHz、双声道、16-bit PCM
└── mix.mp3      # 从同一 WAV 编码，192 kbps
```

流程：结构化乐谱 → Mido 的实际多轨 MIDI → FluidSynth 浮点 WAV → FFmpeg 峰值限制/时长整理/PCM WAV → libmp3lame MP3 → FFprobe 格式与时长核对。

保留完整工程时间轴与空白区间，末尾加固定 3 秒尾音，最后 50 ms 淡出。新建歌曲的默认时间轴为 60 秒，所以几秒演奏加入新工程后也会导出 63 秒音频。尾音策略用于本阶段手动工程；未来 AI 的“60 秒短曲”结束口径仍须另行定义。

WAV 时长容差为约 1 个采样点，检查非静音、电平及整数削波样本；最终 PCM 峰值限制在 0.95 附近。MP3 格式核对为 44.1 kHz 双声道，容器时长与目标差不得超过 0.1 秒；有损编码和解码器延迟不属于 WAV 时长承诺。没有完整响度/真峰值/主观质量评测。

最多 4 个运行/排队任务，单进程串行执行，避免同时消耗大量 CPU。每次工具调用最长 120 秒；超时、缺资源、不可发声的乐谱、磁盘失败等明确失败，用户手动再试。重复发起同一版本/模式/音色/方案可复用已有成功结果；缺失结果文件时重新生成。

工具使用参数数组启动，不拼接用户文件名或命令字符串，Windows 不打开额外窗口。临时工作目录在经过范围校验的任务目录内；完成检查后逐文件原子发布，最后更新成功标记。半成品不开放下载，失败不覆盖以前任务或歌曲版本。渲染状态读写使用同一锁，避免 Windows 轮询期间的文件替换冲突。

任务和音频历史不需要数据库。重启能列出并试听/下载完成结果；本次进程未持有的未完成任务标为中断，不能假称完成，也不自动重试。关闭服务时正在运行的本地工具可能继续收尾至完成或超时；此阶段不提供暂停/取消/跨重启续跑。

## 文件职责与接口

| 位置 | 职责 |
| --- | --- |
| `backend/app/resources.py` | 固定本地工具路径、SF2 文件校验、音色目录和 GS 预设检查；不读取密钥配置。 |
| `backend/app/render.py` | 有限任务队列、版本绑定、实际渲染、音频检查、失败保护、历史与下载路径。 |
| `backend/app/main.py` | 本地资源、渲染任务和音频接口；继续保护主机、来源与写操作会话。 |
| `frontend/app/src/audio.ts` | 本地音色加载、实际采样发声、音频线程回放和电平。 |
| `frontend/app/src/AudioExports.tsx` | 模式选择、任务状态、历史试听/下载与旧结果标记。 |
| `scripts/check_audio.py` | 只读资源/工具排错，需用 Conda piano；不代表音乐质量测试。 |

主要接口：`GET /api/audio/resources`；`GET /api/audio/soundfont?sha256=...`；`POST /api/projects/{id}/renders`（基础版本、模式）；`GET renders` / `GET renders/{job}`；`GET renders/{job}/audio/wav|mp3`。音频下载支持 Range，用于浏览器流式试听；加 `download=true` 请求附件。只能访问固定格式的已完成本歌曲文件，不接受任意文件路径。
