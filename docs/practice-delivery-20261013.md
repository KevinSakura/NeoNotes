## 启动与使用

停止旧服务，重新双击项目根目录 `启动工作台.cmd`，浏览器打开 `http://127.0.0.1:8000`。启动脚本继续使用Conda `piano`、现有音频资源及单个FastAPI进程，不创建Python环境。顶部选择“练习”；默认仍打开创作，切换会停止声音并保留创作草稿。

本机已安装并锁定 `opensheetmusicdisplay@2.1.3`。新机器按现有 `scripts/setup_frontend.ps1` 从锁文件安装；Python依赖未新增或降级。OSMD用于浏览器SVG记谱，[官方项目](https://github.com/opensheetmusicdisplay/opensheetmusicdisplay)、[版本记录](https://github.com/opensheetmusicdisplay/opensheetmusicdisplay/releases)、[GraphicalNote接口](https://opensheetmusicdisplay.github.io/classdoc/classes/GraphicalNote.html)已核对；完整BSD-3-Clause许可保存在 [licenses/osmd-BSD-3-Clause.txt](licenses/osmd-BSD-3-Clause.txt)。安装新增76个前端包项，未运行依赖安装脚本。歌手资源不是练习依赖。

实际流程：导入MIDI → 明确选轨及1–16小节 → 核对整理及试听 → 确认保存独立练习版本 → 认音轮 → 从头开始节奏轮 → 查看/恢复/下载记录。也可从创作当前明确保存版本复制材料；复制的是该版本乐谱导出的MIDI，关联歌曲ID及版本ID，不声称取得原始上传文件。

隔离固定材料可用 `.cache/practice-evaluation/implementation-20261013/simple-score/source.mid`（四个起音组，含黑键及三和弦）和 `fixed-score/source.mid`（八小节，含90→120BPM、变拍、跨小节/跨行延音、重复同音与三连音）。在练习页导入这些文件即可自行核验，不需要调用模型或歌声。

## 实际实现

| 模块 | 当前行为 |
| --- | --- |
| 入口/声音所有权 | React顶部创作/练习按钮；创作保持挂载与草稿，隐藏时禁用创作键盘。练习独立实例、发声句柄与通道；切入口/失焦/后台/暂停/表单焦点释放原声音，异步加载受epoch保护。 |
| MIDI材料 | 独立Mido Type0/1正PPQ解析；保存原字节、SHA-256、原始事件、原PPQ及480PPQ转换舍入。按原轨/通道查看，多轨共用通道不折叠身份。未声明Program/Bank显示缺失，默认速度/拍号标明。 |
| 整理 | 明确量化网格、谱表、声部、片段、八度移调、弱起及调号拼写；量化偏移逐音报告，明显偏移需确认；同音重叠按FIFO配对并提示，独立起音不合并。每谱表最多两个推断声部，大谱表最多四个；来源不足时只标推断。 |
| 五线谱 | 自有note/segment/attack ID，MusicXML带谱号/调号/拍号、标准时值、休止、连线、变速/变拍。谱号等仅在开头或变化处声明，OSMD负责系统开头重显。连续等值三连音按组三连音标记；孤立比例时值显示3:2，复杂分组仍需人工核对。 |
| OSMD映射 | 对象层以小节/谱表/声部/时间/实际MIDI音高匹配自有ID；`getNoteheadSVGs()`返回整个和弦，使用`vfnoteIndex`定位单音头。点击/键盘Enter、高亮及重新排版重建映射；缺失/非唯一时禁用确认和练习，不依赖SVG坐标推导时间或XML ID直传。 |
| 认音 | 100ms内聚合一次答案，目标集合完全一致且曾同时按住才推进；缺音、额外音和纠正独立保存。认音不考核速度，全部最终正确后明确开始节奏轮。上一目标保持不自动作答下一题。 |
| 节奏 | 独立从片段头重启，0.5/0.75/1倍、预备拍和AudioContext节拍器；按完整速度图计算原始输入期望时间。提前/滞后、音高、漏音、额外及整体休止误按分开；有实时文字反馈。 |
| 延音/圆滑线 | 一个来源note跨小节拆多个音头，仍仅一个起音目标，链末才判断松键；相邻同音新note-on仍各自起音。圆滑线由用户明确添加，不推断MIDI原演奏意图，线内不同音仍分别起音。 |
| 记录 | 每次原始键/逻辑音/down/up、按键与处理时刻、尝试、反应/纠正耗时、节奏偏差、帮助/暂停/未完成状态、规则及校准快照保留。首次组正确比例、首次音高准确率与累计准确率分别计算；下载完整JSON。 |
| 保存与恢复 | IndexedDB缓冲、每秒/题结束批次自动保存；序号＋一致哈希幂等，冲突拒绝覆盖。暂停、速度变更及刷新续练创建新节奏段，从保存小节或整条延音起点重新预备，旧段不合并为无错成绩。后端重启将活动未完成会话标中断；批次文件为事实来源，摘要可重算。 |

输入纯函数沿用仓库 `.mjs` 便于直接Node重放，页面/持久化队列为TypeScript；后端有Python同规格规则。没有新增数据库、AI生成或歌声协议。主要源码位于 `frontend/app/src/practice/`、`backend/app/practice_*.py`，入口改动在 `Root.tsx`、`App.tsx`、`main.py`，音频引擎增加练习时钟与发声接口。

## 用户确认的键位与评分

默认基础八度4：s/d/f/g/h/j/k/l为C4/D4/E4/F4/G4/A4/B4/C5；e/r/y/u/i为C♯4/D♯4/F♯4/G♯4/A♯4。

- 单按Shift/空格，最后松开且此次未参与演奏时，整体切低/高一档；基础3–5档，边界不继续移动。
- 按住Shift/空格弹音符，基础音加低/高八度共同发声，不切档；例如Shift+d=D4+D3。音符先按再按单个修饰，也在修饰时刻新增副音，原基础音不重触发。松修饰仅释放副音，松音符释放该键全部声音。
- l是普通高C，立即起音；默认d+l=D4+C5。原60ms等待、l叠加及锁定方案已经用户替换。
- 左右Shift按一组处理；双修饰拒绝新音，已有声音保持。repeat、重复keydown与焦点变化不会重算释放音高。
- 只应用练习；创作仍使用原A/W/S/E/D/F/T/G/Y/H/U/J/K键位。

独立音域C3–C6，跨八度组合实际发声C2–C7。检查同时保持的音高集合，首版节奏只放行能以单档普通键或一种双音模式直接完成的集合；依赖复杂修饰历史的组合保守阻止，提示选声部、选段或显式移调。C3+E4、独立D6等不能因“通过自检”绕过限制；D5+D6可直接双音。多键自检只证明浏览器收到哪些事件，不能证明未上报的物理键存在，也不能放宽音高匹配。

规则版本 `neonote-practice-rules-1.0`、映射 `tap-register-held-octaves-v2`。认音首次组准确率＝首次完整正确组数/已提交组数；首次与累计音高准确率＝TP/(TP+FP+FN)，首次错误不会被后来纠正覆盖。未答为未测量；中断尝试另有标记并保留原事实，不伪造成已正确答案。

节奏宽匹配窗250ms，同音按相邻目标中点划半开区间，窗内选最近未匹配输入、同分按输入顺序；准拍窗为局部四分音符练习时长的20%，限制60–150ms。准拍率分母包含全部应起音目标，漏音不消失。松键容差为max(120ms,时值20%)，圆滑间隙80ms、和弦齐奏100ms仅提示，不增加解锁门槛。建议达标音高≥90%、准拍≥80%、休止误按0，完成时间线和建议达标是两件事。

输入用KeyboardEvent原事件时间；AudioContext调度并通过getOutputTimestamp建立听到时刻对应，缺接口时采用标示估计的输出延迟。八拍敲击校准包含个人反应，校准状态/偏移随新会话保存，不依据错拍自动调分。画面刷新只用于显示、提示实际目标就绪及发现时钟异常；评分可由记录重放。暂停恢复、长主线程间隙和音频时钟异常不会把整段未来目标算漏音。

## 保存位置与完整性

```text
data/.practice/
  materials/<material-id>/
    source.mid / source.json / parsed.json
    revisions/<revision-id>/
      revision.json / settings.json / notation.json / targets.json / score.musicxml
  sessions/<session-id>/
    session.json                 # 完整目标/规则/哈希/初始速度/校准/进程epoch
    events/000001.json           # 每批序号、负载哈希及逐事件记录
    attempts.json / summary.json # 可由事实批次重算
```

原字节与解析结果、不可变整理参数/谱/目标/XML、会话目标/规则及批次均有哈希核对。临时文件fsync后原子替换，发布元数据最后写入；无完整发布记录的材料不参与列表。不同内容同序号拒绝，失效的目标/规则/XML拒绝读取。成功批次已经落盘而摘要失败时，可幂等重发并由批次恢复。

IndexedDB `neonote-practice-buffer-v1` 是待发送队列，后端JSON是权威记录。保存失败请保留同一浏览器和站点缓存，重试或下载记录；清除浏览器缓存可能丢未落盘部分。异常关闭保留未完成，不自动判通关。练习复制对创作只读，删除/恢复原歌曲不移动练习副本，不改歌曲审核、人声或版本状态。首版未提供练习材料/会话删除，备份应包含整个data目录。

## 实现差异与剩余范围

- 原设计l等待/高八度叠加已由用户正式替换；实际应用顶部按钮而非单独两张入口卡。
- 支持材料2MiB、5000个起音、原时间轴10分钟；每次练1–16小节。支持2/4、3/4、4/4、6/8与小节边界变拍；中途变拍、无法精确表达时值、SysEx/未知系统事件及片段中的弯音拒绝，原始文件仍保留。踏板/表情/途中音色需确认忽略，试听均钢琴，不能称为原演奏完整复现。
- 声部、音名拼写、记谱延音、圆滑表达均有推断/用户来源。跨边界持续音默认拒绝，可明确扩展完整边界；不实施“切断后重新起音”。重叠同音可明确选择分离声部，不合并目标。
- 可达性采用保守子集，复杂修饰历史与持音组合可能被阻止；首版没有全局指法规划。屏幕和弦辅助只用于认音；节奏屏幕多点仍要求真实同时输入，不合并多次探索答案。没有外接MIDI控制器、扫描谱识别或任意MusicXML导入。
- 同音匹配按不重叠中点归属窗，单独定义可复核合同，不采用任意窗口的全局最优匹配。保持/圆滑/和弦齐奏是提示，未做自动纠错、专业踏板判定或奖励调整。
