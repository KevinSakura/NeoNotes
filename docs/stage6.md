# 第六阶段：审核短曲后的整曲生成

后续更新（2026-10-06）：用户已将有歌词流程改为全文一次谱曲，不再以60秒选段审核为前置。64行/1024字词、按全文安排时长，新合同不由模型维护全局音符编号；2次真实技术复验通过，详见[歌词重写交付](lyrics-rewrite-20261006.md)。本页初交付的零真实调用、61–600秒和短曲审核要求是历史记录；无歌词及旧短曲审核流程仍保留。

日期：2026-10-06。正式后端0.6.0、stage6。本阶段由用户明确要求开始整曲生成，并将输出token上限调整为32768。

## 用户确认的范围

- 从已采用、已保存且人工试听/试唱审核通过的60秒短曲开始；审核不会自动发起整曲请求。
- 沿用短曲旋律和风格，按全歌词顺序重新安排整曲，不将原60秒逐秒固定为开头。
- 有歌词时自动使用上传TXT中的全部非空歌词行，时长按全部歌词和乐句安排；无歌词固定3分15秒，即195秒。
- 保留键盘、鼓、吉他、贝斯四声部、手动编辑、不可变历史、MIDI和本地渲染音频；首版仍不合成人声。
- 正式歌曲与HTML原型保留。开发助手新增真实付费请求仍须单独授权，本阶段实际新增真实请求0次。

## 启动和操作

1. 停止旧版本服务，再双击根目录[启动工作台.cmd](../启动工作台.cmd)，或在项目根目录运行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_local.ps1
   ```

2. 用Chrome/Edge打开 **http://127.0.0.1:8000**。原有`.env`与SoundFont无需重新准备，启动和打开页面不调用模型。
3. 上传完整歌词TXT，先选择短曲选段并生成60秒候选；也可不使用歌词。试听后明确采用到编辑器。
4. 在“03 保存与导出”核对当前保存版本，亲自完成旋律、四声部、曲风检查；有歌词时照词试唱，再记录审核通过。
5. 在下方“从已审核短曲生成整曲”查看全歌词行数/字词数及调用规则。真实模式还须勾选本次发送资料及付费确认，再点击“AI生成整曲候选”。模拟模式显示“模拟生成整曲候选”，不会请求API。
6. 候选完成后试听、查看全部歌词与音符对应，明确采用。此时创建新版本，短曲和原审核保留，新整曲没有自动通过审核。
7. 编辑或逐句练唱，再保存；可下载真实多轨MIDI，并发起本地WAV/MP3渲染。整曲也支持自然语言整体修改，保持当前时长与全歌词，新修改仍作为候选处理。
8. 若要重新生成另一份整曲，在编辑页撤销采用或从历史恢复短曲。恢复为新版本时须重新审核；不要从整曲版本再次自动续写。

模拟短曲及模拟审核只能用于模拟整曲。真实模式需要真实短曲的人工审核，不能将模拟流程换一个模式后当作真实质量验收。

## 时长、旋律与歌词规则

短曲仍严格为60秒，音乐时间轴容差0.001秒。整曲在现有10分钟/5000音符工程上限内运行：有歌词时由模型返回61–600秒整数时长，程序检查其完整音乐内容和全部字词对应；无歌词必须为195秒。有歌词不强制固定3分15秒，也不静默删词、增词或重复原文；需要重复副歌时，应在TXT显式写出重复歌词行。

2026-10-06用户追加要求后，整曲全文上限为64个非空行、1024个中文字符或英文词；短曲选段上限为16行、256字词。超出上限在请求前提示，不裁剪输入。歌词选段在短曲历史中保留，整曲候选自动选择全文的非空行，原行号、原文字和来源文件信息保持可追溯。粘贴到歌词框的完整文本也按同样规则处理。短曲未选歌词时可用主题、音乐感觉或演奏生成器乐候选，存储的全文不作为本次短曲歌词发送；整曲仍使用全文。修复说明和追加验收见[歌词输入修复记录](lyrics-input-fix-20261006.md)。

工程中记录`composition.scope`、`target_seconds`及`full_source`。`full_source`引用已审核短曲版本和不可变审核ID，并保存一个最多8音的参考音高片段：优先取已绑定歌词的开头音符，无歌词时取键盘开头音符。模型须在整曲键盘旋律中连续出现该音高片段，位置和节奏可重新安排。程序检查该基础匹配，人工仍须判断是否实际沿用了短曲旋律、曲风和发展思路；匹配8音不等于艺术质量达标，也没有评估转调或更自由的旋律变体。

用户原演奏的`preserve`约束继续有效：原音高、力度、秒位置/时长及Program/Bank仍由程序固定，模型在原演奏参考窗口后延展。重新组织的是已生成短曲的段落，不自动解除用户此前选择的原演奏保留约束。`extend`模式仍需人工对照走向利用。

四声部共享时间、段落与和声；每声部参与至少两个共同段落，无同音重叠，整体发声间隙不超过3秒，最后实际发声距曲末不超过0.25秒。歌词保持全部字词对应、单旋律、规定音域和音符时长、行间换气。结构核对不评判中文重音、英语音节或真实可唱性。

## 32768配置与失败处理

`.env.example`及默认`MODEL_MAX_TOKENS`已更新为32768，允许配置512–32768。**整曲生成及整曲的整体修改单次固定发送32768，即使原`.env`仍填写12000也生效。** 短曲与短曲修改仍尊重原配置；若希望它们也使用32768，由用户在本地自行修改该数值并重启。开发助手没有打开、修改或展示真实`.env`。

单次超时仍按`MODEL_TIMEOUT_SECONDS`配置，默认180秒，当前支持10–300秒。较长响应可能超时；可由用户自行调整到300并重启。提高输出上限只增加可用预算，不能保证一次生成完整、可唱且高质量的歌曲。当前DeepSeek官方接口支持32768；`finish_reason=length`仍可能返回截断内容，详见[官方Chat Completions文档](https://api-docs.deepseek.com/api/create-chat-completion/)和[JSON Output说明](https://api-docs.deepseek.com/guides/json_mode/)（2026-10-06核对）。

每个任务仍最多一个请求，不自动重试、不拆成多次付费调用、不切换服务商。原始密钥、原始HTTP响应不进入前端或历史。任务记录实际分发尝试、采用的输出上限、可确认的返回用量和失败原因；失败可能计费，以服务商账单为准。旧第三/第五阶段预算不延续，不重新分配第五阶段剩余1次。

输出截断、非法JSON、段落/时长/歌词缺失、参考旋律丢失或音色不可用时拒绝候选，不用补静音、猜词或自动修复冒充成功。新版本保存后旧审核失效；审核撤回或重新审核后，也不能采用基于原审核的旧整曲候选。审核来源与不可变历史缺失/不一致时，在请求前阻止生成。

## 数据位置

正式数据继续在`data/<歌曲ID>/`，没有数据库。短曲和整曲的输入、不可变版本、候选及音频使用现有目录：

```text
data/<歌曲ID>/
├── inputs/<版本ID>/             # 原始歌词文本、选段、演奏与文件来源
├── revisions/<版本ID>.json     # 短曲、采用整曲及修改版本
├── jobs/composition/<任务ID>/  # operation=full或modify，scope、输出上限及来源
│   ├── input.json              # 全歌词及审核短曲参考，无密钥
│   ├── job.json                # 状态、请求数、用量、结果时长
│   ├── plan.json               # 通过检查的完整音乐规划
│   ├── candidate.json
│   └── candidate.mid
├── reviews/<版本ID>.json       # 版本最后一次审核
├── reviews/history/<审核ID>.json
└── exports/audio/<渲染ID>/     # mix.mid、mix.wav、mix.mp3及版本绑定记录
```

音乐时间轴与渲染尾音分开计算：无歌词195秒整曲的WAV约198秒；其他整曲WAV为自身时间轴加3秒，末尾50ms淡出。MP3另有少量编码延迟，不当作创作时长。

## 剩余风险与人工验收

整曲的新提示尚未真实调用验证，已有60秒真实作品/失败记录不证明长曲效果。本阶段交付软件路径及离线证据，不能声明DeepSeek已经稳定生成完整优质歌曲。后续真实验收需要新的明确调用预算及真正人工审核通过的短曲来源。

人工必须核对：全歌词是否能原速唱完且重音/换气自然；整曲旋律与曲风是否沿用短曲；多段发展是否自然；四声部是否配合；尾奏是否收束；导出的最终MP3是否完整可接受。达成标准见[人工验收清单](manual-acceptance.md)。首版仍没有合成人声，MP3中的键盘主旋律是歌词演唱指南；仅有器乐音色不代表歌词没有处理。

局部AI修改、单声部重生成、人声、自动音节/声调优化及其他乐谱格式仍未实现，不自动开展下一阶段。
